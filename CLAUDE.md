# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

ExamCards is a Unity 6 (`6000.6.3f1`, URP 2D) quiz game. The player sees exam questions one at a time. Each question has several answer cards, and exactly one is correct. A **Reveal** button swaps the current question's text for a simplified version, and a **search** modal (header button or `/`) finds any question by text and plays it right away. Questions come from a FastAPI backend (`/v1/game` routes, `http://127.0.0.1:8000` by default) in both the Editor and player builds; the game never talks to the database, and the backend, not the game, decides whether an answer is right. The UI is built with **UI Toolkit** (UXML/USS), not uGUI. It started from the Figma file "ExamCards" (`yklzlKknayD83RhAn8BCRM`), page **PickOne** (root frame `4:2`, 1280×1024), and has since been reworked for long, text-only questions.

## Architecture

- **Domain — `Assets/Scripts/Exam/`** (asmdef `ExamCards.Exam`, `noEngineReferences: true`, so it is plain C# and unit-testable):
  - **The client never holds the answer key.** `Question` is what the player sees: `Original` and optional `Simplified` `QuestionPrompt`s (question text and answers only). The correct answer, per-answer feedback and explanation arrive only after answering, as an `AnswerReview` (`CorrectIndex`, a `PromptReview` for each version (`Simplified` is null when there is none), and `AnsweredIndex`: null for "the answer sent", or the earlier answer the round had already recorded).
  - `IExamRound` is one round held by whoever has the key: its starting `Questions`, `FiftyFiftyCharges`, `HasMore`, `SubmitAnswerAsync(questionId, index)` → `AnswerReview`, `EliminateAsync(questionId)` → `FiftyFiftyResult` (removed indices and the round's charges left), and `FetchMoreAsync()` → the next batch of questions it hasn't had (empty when used up). Each question is answered once; the same answer (or 50/50) again repeats the result, and a *different* answer returns the one recorded first, so a lost response can't leave a question stuck.
  - `IExamRound.AddQuestionAsync(questionId)` adds a question (a search result) to the round so it can be answered there; adding one it already has returns it again. `Questions` stays the starting list.
  - **Visual entities** (`VisualEntity.cs`): a simplified `QuestionPrompt` has `Entities` (`PromptEntities`: `Question` and one list per answer, `ForAnswer(i)`), each a `VisualEntity` (`Name`, `Kind` actor/object/action, `Aliases`, `Icon`) the backend extracted from the texts. Originals, search results and questions extracted before entities have `PromptEntities.Empty`.
  - **Icon keys:** the backend, not the game, decides which icon fits. It picks from its icon catalog (`../exam-explainer-api/src/claude_exam/api/icon_catalog.py`) and sends provider-neutral keys (`subagent`, `config-file`): `VisualEntity.Icon`, `PromptEntities.QuestionIcon` (the question as a whole) and `AnswerIcons` / `IconForAnswer(i)` (what each answer proposes; it need not be one of the answer's entities). Any of them can be null. `EntityIconResolver.Resolve(entity)` returns the entity's key or the key of its kind (`actor`/`object`/`action`); `CleanKey` accepts only lower-case words joined by hyphens, because a key is used as a resource name; `DefaultIcon` is for a question or answer without a key.
  - **Learning objectives:** the backend tags questions from its objective catalog (`../exam-explainer-api/src/claude_exam/api/objective_catalog.py`). `Question.Objectives` holds the keys (main one first, empty when untagged) and `Question.Difficulty` is 1–3 (0 when untagged). `AnswerReview.Misconception` is one sentence on what the answer that counts suggests the player got wrong (empty for a correct answer or an untagged question); like the rest of the key it only arrives after answering. The mapper drops anything that isn't a key instead of failing a round. Nothing in the UI shows these yet; they are the data for the planned map and mastery tracking. `GET /v1/game/objectives` (catalog with playable counts) and the `objective` filter of `POST /v1/game/rounds` exist on the backend but the game doesn't call them yet.
  - **Story:** the backend frames the bank as one story (`../exam-explainer-api/src/claude_exam/api/scenario_catalog.py`): one company, a chapter per exam scenario, the same stages in each. `Question.Scenario` and `Question.Stage` are the chapter and stage keys, `Question.Beat` one line to show before the question, and `Question.Stem` the original text without the scenario paragraph the source repeats in every question of a chapter; all are empty when the backend has none. `Question.OriginalText` is what to show for the original (the stem, or the whole text without one). `AnswerReview.Outcome` is the story line for the answer that counts and, like the rest of the review, only arrives after answering. The mapper trims the lines and drops a key that isn't one. `GET /v1/game/story` (chapters and stages with counts) and the `scenario` / `stage` / `ordered` fields of `POST /v1/game/rounds` exist on the backend but the game doesn't call them yet: rounds are still random, and the map that would use them is planned.
  - `IQuestionSearch.SearchAsync(text)` finds playable questions (no key, no simplified text; `QuestionSearchText.Normalize` collapses whitespace and line breaks, trims, min 2 / max 2000 chars, so a whole pasted question fits). The API and mock services implement it.
  - `IQuestionService.StartRoundAsync()` starts a round (throws `NoQuestionsException` when nothing is playable). `QuestionServices.Create()` picks the service: `Factory` if set (the API assembly sets it), otherwise `MockQuestionService`, which EditMode tests use. A round can't be replayed, so Play Again starts a new one.
  - `LocalExamRound` is an `IExamRound` over `KeyedQuestion`s (question + review) with the same rules as the backend; the mock and the tests use it. Its optional `catalog` holds questions `AddQuestionAsync` may add (the mock's search finds two extra questions there), and `more` (with `batchSize`) feeds `FetchMoreAsync`, skipping anything already in the round.
  - `QuestionValidator` checks questions (1..`Question.MaxAnswers` (4) answers, simplified has the same count), reviews (correct and recorded index in range, one feedback per answer) and 50/50 results, throwing `FormatException` that names the question.
  - `Api/GameQuestionDtos.cs` mirrors the backend's JSON as `[Serializable]` classes with snake_case public fields, as `JsonUtility` needs. `Api/GameQuestionMapper` turns a round or batch response into `Question`s (answers ordered by `index`; rejects duplicates, wrong `simplified` flags, simplified versions without an original and a batch for another index), maps `entities` leniently (an entity without a name or with an unknown kind is dropped, answer entities and icons that don't line up with the answers are ignored, an `icon` that isn't a key becomes null; entities never fail a round), and answer/50/50 responses into reviews and `FiftyFiftyResult`s (rejecting a response for another question, one whose `is_correct` contradicts `correct_index`, or one without a review, since `JsonUtility` turns missing fields into defaults instead of failing).
  - `ExamSession(round)` walks the questions and keeps score and lives (`MaxLives` 3, a wrong answer costs one; the exam ends after the question that uses the last). **One round goes on in batches:** when the current question is answered, it is the last one loaded and the round `HasMore`, `NeedsMore` is true; `LoadMoreAsync()` appends the round's next batch (never a question already played or added by search) and `MoveNext()` then continues, so the exam runs until the lives or the questions run out (`IsLastQuestion`). `MoveNext()` throws while `NeedsMore`. The answer that counts is `review.AnsweredIndex ?? the pick`; the 50/50 count is taken from the round. `AnswerAsync(index)` and `EliminateAsync()` go through the round; only one runs at a time (`IsBusy`), and a failure leaves the question unchanged so the player can try again. `CurrentReview`/`CurrentPromptReview` hold the feedback for the shown version. `Reveal()` switches `CurrentPrompt` to the simplified text until the next question and doesn't affect the score. `MoveNext()` throws if the current question is unanswered or a request is running, and returns false and sets `IsFinished` at the end.
  - `PlayNowAsync(questionId)` (search) makes a question current: one later in the exam moves up; a new one is added through the round first and counts towards `Total`. An answered current question stays put; an unanswered one is shown again right after. Returns `AlreadyCurrent`/`AlreadyAnswered` without changes; throws when `!CanPlayNow` (busy, finished or out of lives). `IndexOf(id)` tells where a question is in play order.
  - **50/50** removes two wrong answers (`EliminatedPerUse`) from the current unanswered question, once per question, within the round's charges (2 by default); the round picks them, because only it knows which are wrong. Eliminated answers are kept per question id, so a question skipped by `PlayNowAsync` keeps them.
- **Backend API — `Assets/Scripts/Exam.Api/`** (asmdef `ExamCards.Exam.Api`, all platforms):
  - All paths start with `ApiQuestionService.Prefix` (`/v1`). `ApiQuestionService.StartRoundAsync` sends one `POST /v1/game/rounds {"count": N}`, which returns the questions and their simplified versions without the answer key (`HasMore` when the backend's `total` exceeds them). `ApiExamRound` then posts to `/v1/game/rounds/{round_id}/answers`, `/fifty-fifty`, `/questions` (add a search result) and `/batches {batch_index, count}` (`FetchMoreAsync`; the index only advances on a non-empty batch, so a retry gets the same batch). On 409 `already_answered` it reads the recorded answer from `GET …/answers/{question_id}`. `SearchAsync` sends `GET /v1/search/game-questions?q=&limit=`. Rounds expire on the server after a day.
  - HTTP goes through `IHttpTransport`: `UnityWebRequestTransport` in the game (main thread only, awaited with `Awaitable.FromAsyncOperation`; cancelling the token aborts the request, so cancel on the main thread), a fake in the tests. `GameApiClient` sends JSON (`PostAsync`, `GetAsync`) and throws `ApiException` (method, URL, status, the backend's `detail` and `Code`, e.g. `ApiErrorCodes.AlreadyAnswered`) or `FormatException` for a bad body. An idempotent request (everything except starting a round) is retried once after `DefaultRetryDelaySeconds` (0.5 s, via `Awaitable.WaitForSecondsAsync`) on a transient failure: no response, 5xx or `round_changed`.
  - `ApiQuestionService` registers itself as `QuestionServices.Factory` in `[RuntimeInitializeOnLoadMethod(BeforeSceneLoad)]`.
  - `ExamApiSettings` (ScriptableObject at `Assets/Resources/ExamApiSettings.asset`, created by the setup menu) holds the base URL, questions per round and per later batch (10, max 50), search results per query (8, max 50) and request timeout. Without the asset the code defaults apply. `TryValidateBaseUrl` requires an absolute http(s) URL; `OnValidate` warns in the Inspector.
  - Plain `http://` is allowed only in the Editor and development builds (`PlayerSettings.insecureHttpOption = DevelopmentOnly`). `Assets/Editor/ExamApiBuildCheck.cs` fails a build with an invalid URL, and a release build whose URL isn't `https://`.
  - The backend's OpenAPI spec is at `<base URL>/openapi.json` (docs at `/docs`). Its source is the sibling repo `../exam-explainer-api` (`src/claude_exam/api/routers/game.py`).
- **UI — `Assets/UI/PickOne/`** (lives in Assembly-CSharp):
  - `PickOne.uxml` is the whole screen. `AnswerCard.uxml` is the per-answer card template, instantiated from code into `cardsRow`.
  - `PickOne.uss` holds all styles. The palette lives as `:root` variables.
  - `PickOneScreen` (MonoBehaviour on the `UIDocument` GameObject) starts a round and handles card picks (click or keys 1–4), Reveal (click or R), 50/50 (click or F), and Next, Play Again and Retry (click, Enter or Space), then shows the results overlay. It creates the question service inside the load, so a bad setting ends in the failure message too. A failed or empty load (including `NoQuestionsException`) shows a message and the Retry button; in a player build a missing service factory is logged as an error instead of quietly serving mock questions. Next on the last loaded question loads the round's next batch (`LoadMoreAndAdvance`, status "Loading more questions…", Next retries a failure), and the results show score out of answered questions. A failed answer or 50/50 shows `statusText` (in the question's chip row) and leaves the question playable. `RenderPrompt()` draws the current text and state, and runs for a new question, an answer, a 50/50 and a reveal. Cancelling `_roundCancellation` (on disable and on each new round) drops any request still running.
  - **Story on the screen:** `RenderPrompt()` shows `storyBeat` above the question, `Question.OriginalText` instead of the full original text, and `storyOutcome` at the top of the explanation once answered. `chapterChip` (chapter and stage, hidden without a chapter) toggles the full text with its scenario paragraph for the current question (`_showScenario`, reset per question). The simplified text is shown as it is: the backend writes it as the question's game text, in plain words and set in the story (with the chapter's people), and leaves it out when its check finds the rewrite changed which answer is right, so Reveal is then unavailable for that question.
  - `SearchPanelView` is the search modal (`searchOverlay`): debounced text field (300 ms), status line, result rows built in code (section chip, a NEW / IN THIS ROUND / CURRENT QUESTION / ANSWERED chip, question and answers, never the correct one), arrow-key selection. The text field is multiline only so long text wraps (it grows to 160 px, then scrolls): a trickle-down `KeyDownEvent` handler keeps Enter and ↑/↓ from the field (so they only play / move the highlighted result) and pasted line breaks become spaces. Its `max-length` (8000) is above `MaxTextLength` on purpose, so whitespace is collapsed before `Normalize` cuts the text. `PickOneScreen` runs the search (cancelled by the next one, by closing and on disable) and plays the chosen result via `ExamSession.PlayNowAsync(id, reveal: true)`, so the question opens on its simplified text (when it has one; R shows the original; the current question keeps the text the player chose); a failure keeps the modal open with a message. While it is open, `Update` hands keys to it (Esc, ↑/↓, Enter) and the question shortcuts are off.
  - `AnswerCardView` binds one card's text and switches state only through USS classes (`answer-card--interactive|correct|wrong|dimmed|eliminated`). `Bind` doesn't touch state, so a reveal keeps a card's result colours.
  - **Large icons** (`.hero-icon`): `questionIcon` in the question's chip row and `cardIcon` in each card's header (`AnswerCardView.BindIcon`) show `QuestionIcon` / `IconForAnswer(i)`. `RenderPrompt()` takes them from `question.Simplified?.Entities` whichever text is shown, so they are always visible; a question without a simplified version (a search result before it is added) shows `DefaultIcon`. USS tints a card's icon by its state class.
  - `EntityStripView` fills a container with entity chips (icon + name, or icon only with `compact`; kind colours via `entity--actor|object|action`). `RenderPrompt()` takes them from `question.Simplified?.Entities` and shows them for both texts (a reveal swaps only the text): `questionEntities` (up to 8) under the chip row, and each card's `cardEntities` (up to 4, in the header; runtime panels show no tooltips, so card icons have no visible name). `EntityIcons` loads `Resources/EntityIcons/<key>` with a cache (`For(entity)` falls back to the kind, `For(key)` / `Show(element, key)` to `DefaultIcon`); the icon's `background-image` is the other data-driven inline style.
  - **Icon files:** `Assets/Resources/EntityIcons/<key>.svg`, one per key of the backend's catalog. Today they are Lucide glyphs (ISC, `LICENSE.txt` there, v1.69.0) with the stroke in white so the importer has a colour and USS tints them. Don't add them by hand: add the key to the backend's `icon_catalog.py`, run its `scripts/export_game_icons.py` (writes the SVGs here) and `UPDATE_CONTRACT=1` for `tests/test_contract.py` (writes `Contract/icon_catalog.json`). `Assets/Editor/EntityIconImport.cs` imports them as `VectorImage`, and `EntityIconResolverTests` checks every catalog key loads. A key the game doesn't ship only falls back, so the backend can add keys before the game does. Changing the icon set means replacing these files under the same names.
  - `GradientElement` is a `[UxmlElement]` that draws gradients with vertex colors, because USS has no gradients.
  - Lives (`hearts`) follow `ExamSession.Lives`.
  - Header nav, coins, timer, streak and the other two power-ups (Freeze, Codex Lore) are **static placeholders**; they are not wired up yet.
- **Scene setup**: the menu **Tools ▸ ExamCards ▸ Setup PickOne Scene** (`Assets/Editor/PickOneSceneSetup.cs`) creates `Assets/Resources/ExamApiSettings.asset` if missing and `Assets/UI/PanelSettings.asset` (uses theme `Assets/UI/ExamTheme.tss`, scale-with-screen 1280×1024) and wires the `PickOneUI` GameObject into `SampleScene`. Re-run it after changing serialized references instead of editing the scene YAML.

## UI Toolkit conventions in this project

- USS has no `box-shadow`, `gap`, or gradients. The neo-brutal hard shadows are done two ways:
  - **1–2 px offsets:** thicker right/bottom borders.
  - **3–4 px offsets:** a `.brutal.brutal--s3|s4` wrapper whose first child is an absolute `.brutal__shadow`, translated under the real `.box`.
- `name` attributes are camelCase; classes are BEM-style kebab-case. Avoid inline `style` in UXML; the only inline styles set from C# are data-driven values (progress width, an entity's icon).
- Labels showing exam data set `enable-rich-text="false"`, because the text can contain literal tags such as `<example>`.
- Buttons are `focusable="false"`, so Enter and Space only act through `PickOneScreen`'s key handling and don't also trigger a focused button.
- SVG icons in `Icons/` import as `VectorImage` and are referenced from USS via `url("project://database/...")`.
- Fonts: the design uses Outfit and Nunito Sans, but the project currently uses Unity's default font.

## Working with the Editor

- A running Editor can be driven with the Unity CLI: `unity status`, `unity recompile`, `unity command eval '<C#>'`, `unity command capture game_view -- --source screen --save_path ...` (the path is relative to `Assets/`, so delete what you capture), `unity command editor.playmode start|stop`, `unity command console get -- --tail 20 --level warn`, and `unity command editor invoke_menu --path "Tools/ExamCards/Setup PickOne Scene"`.
- Tests: `unity command test run --mode EditMode --filter ExamCards`, or Window ▸ General ▸ Test Runner. The EditMode tests are in `Assets/Tests/EditMode/` (asmdef `ExamCards.Exam.Tests`). `ContractTests` parse real backend responses from `Assets/Tests/EditMode/Contract/*.json`; those files are written by the backend's `tests/test_contract.py` (`UPDATE_CONTRACT=1`), which also fails when they drift, so don't edit them by hand.
- An EditMode test runs on the main thread: blocking on a task (`GetAwaiter().GetResult()`) that awaits a delay deadlocks the Editor, so use `new MockQuestionService(latencyMs: 0)` there.
- The active input handler is the Input System only (`Keyboard.current`), not legacy `Input`.

## Conventions for editing

- Every file and folder under `Assets/` has a paired `.meta` file holding its GUID. Never delete or recreate a file without its `.meta`. Move or rename files so the `.meta` goes with them, ideally inside the Editor.
- `Library/`, `Temp/`, `obj/`, `Logs/`, and `UserSettings/` are generated and should not be touched or committed.
